Stale-fill trust: why 8-step outages hurt the GRU

The scatter-trained GRU loses accuracy under block outages mostly because it reads every forward-filled value as a current reading. The information it needs is still in the window. A Bayes-optimal filter that sees the same 24 steps loses much less.

Claim. On this benchmark, {{EXCESS_RANGE}} of the GRU's block-minus-scatter MSE gap is model failure, not lost information (3 of 3 seeds). The trigger is a stale value at the forecast origin, on sensor 0 or on any other sensor. The cause is that the forecast does not discount a value by its age. The Kalman sensitivity to the last sensor-0 reading drops from {{KF_SENS_0}} at age 0 to {{KF_SENS_9}} at age 9+. The GRU sensitivity goes from {{GRU_SENS_0}} to {{GRU_SENS_9}}.

Matched-budget training on block masks and the age input do not fix this. The age input changes block RMSE by at most {{AGE_VS_ZERO}}.

{{GAP_CHART}}

Oracle: a Kalman filter built from the exact generator parameters (recovered by replaying the generator's random numbers), restarted at the first step of each 24-step window. It sees only the readings that the GRU sees. It also knows the true parameters and the seasonal phase, so it is a lower bound on error. The quantity used here is its gap between masks, not its error level. A full-history filter gives the same gap to 4 decimals.

E3 and E4. The forecast does not discount by age

The sensitivity test perturbs the held sensor-0 value over its stale run and measures how much the forecast moves. The Bayes-optimal forecast trusts a reading less as it gets older, because the AR(0.88) state drifts and the other sensors carry newer information. The scatter-trained GRU does the opposite: its sensitivity rises with age. Block training lowers the whole curve, but the curve stays flat. With 4 times more steps and 32 units, block training starts to bend the curve down at high age.

E5. Which sensors' outages matter

A 2 x 2 factorial uses the real starter masks: sensor 0 gets scatter or block, and the other five sensors get scatter or block. For the scatter-trained GRU the two parts add up, and each costs one third to two thirds of the full gap. For the oracle both parts cost almost nothing. A ridge model with fill x fresh and fill x age terms, trained on block masks, is a learned reference without oracle knowledge. It does not beat the GRU in a consistent way.

Mechanism

Forward fill turns an outage into a constant input that looks like a normal reading. Scatter training almost never shows a constant older than 2 steps. So the GRU learns one fixed weight for each filled value, and that weight is right only for fresh values. Under a block mask, about 15% of origins carry a sensor-0 value that is 5 or more steps old, and other sensors are often stale too. The GRU uses such values at the same or a higher weight than fresh ones. The mask and age channels, which carry the age, enter the GRU additively. A plain 8-unit GRU trained for 600 steps does not learn the multiplicative rule "trust a value less as it ages". Showing it block masks at the same budget does not change that.

This also explains the starter result that age input "does nothing". The age is the right signal, but this model cannot turn it into a discount at this budget.

Scope and limits

  • Synthetic data only: 6 sensors from 5 shared AR(0.88) factors, with a known seasonal term. Real sensor networks with nonlinear or non-stationary dynamics are outside this test.
  • Model: the supplied 8-unit NumPy GRU, 12 epochs x 1600 windows, learning rate 0.025. E4b tests 48 epochs and 32 units, nothing larger.
  • Three data seeds. Stale-window results rest on about 21 to 23 outages per seed. The direction of every main result holds in 3/3 seeds, with the exceptions named above.
  • The oracle knows the true parameters and the seasonal phase. It shows that the information is in the window, not that a learned model can reach the oracle error.
  • Dev partition only. The reserved test partition and the value-dependent mask were not loaded or run.

Next steps

  1. Step 2: an age-matched test of the trust mechanism Hold the stale age fixed and swap only the value. Replace the stale fill by the fresh true reading and by the oracle's filtered estimate. If stale-fill trust is the mechanism, the GRU's excess on stale windows goes away with the oracle estimate. If it stays, the hidden state is the problem.
  2. Step 3: one targeted training change, tested on the mechanism Feed the fill deviation through a learned per-sensor decay, (fill − mean) · exp(−γj · agej). This is the input-decay part of GRU-D (Che et al. 2018), so the module is background. The contribution is the test: at the same budget, against the block-trained age-input GRU, the mask-aware recurrent baseline and persistence, does the sensitivity curve turn age-decaying, and does the stale-window loss drop. Score both, not RMSE alone.
  3. Step 3 alternative: a reliability diagnostic Predicted excess per window = Σj |∂forecast / ∂fillj| · drift(agej), where drift is the AR variance growth that can be estimated from training data. Check on dev whether it ranks windows by real error better than sensor-0 age alone.
  4. A limit statement that already holds On this benchmark, scatter-trained plain-GRU forecasts are not reliable when any sensor's age at the origin is 3 or more, not only sensor 0. Persistence is reliable only when sensor 0 is fresh.
  5. Freeze, then run the reserved test Freeze the claim, the decay module or diagnostic, and all settings. Then run --final once, and also evaluate scatter and block masks on the test period, so time-period and mechanism effects stay separate.
