Why long outages hurt the GRU forecaster

When readings are missing in long blocks, the GRU uses old filled values as if they were new. The information it needs is still in the input window. So most of the extra error is a failure of the model, not a loss of information.

1. The problem

Six sensors give one reading per time step. A model reads the last 24 steps of all six sensors. It then predicts sensor 0 six steps later. Some readings are missing. Before the model sees the data, each missing reading is replaced by the last known value of that sensor. This is called forward fill.

Window
The 24 past steps that the model reads for one forecast.
Forecast origin
The last step of the window. The forecast starts here.
Age
How many steps ago a sensor gave its last real reading. Age 0 means a fresh reading.
GRU
The small recurrent neural network (8 units) from the course starter.
Persistence
A simple baseline that repeats the last value of sensor 0.
MSE, RMSE
Mean squared error and its square root. Lower is better.

The course data removes 25% of readings in two ways. The scatter mask removes single readings at random. The block mask removes runs of 8 steps. Both remove the same number of readings per sensor.

The GRU is trained with the scatter mask. On the block mask its error goes up in every seed. Persistence also gets worse. The question of this step: why does the same amount of missing data hurt more when it comes in blocks?

The Kalman filter line is explained in section 3. Seed 942 has about 3 times the error scale of the other seeds, so its bars are longer.

2. Hypotheses: 12 tests in three steps

We tested 12 hypotheses in three steps. Step 1 asks what goes wrong (H1 to H4). Step 1b asks why the GRU does not learn the fix (H5, H6). Step 1c asks if the result holds for a transformer and on real data (T1 to T4, R1, R2). Each was written with its falsifier before its experiment ran. All are fixed in research/HYPOTHESES.md. The cards below explain H1 to H4. H5 and H6 are explained in section 5, T1 to R2 in section 6.

H1 · the given idea

Stale value at the origin

A block that ends at the origin leaves an old value in the last step. The model reads it as a new value.

Wrong if: the error gap is the same when sensor 0 is fresh.

H2

Lost history

Any 8-step hole in the window damages the memory of the GRU, wherever the hole is.

Wrong if: a hole far from the origin costs no error.

H3

Never seen in training

Scatter training almost never shows old values. So the GRU never learned to trust them less.

Wrong if: the best possible model loses as much as the GRU, or block training does not help.

H4

No help from other sensors

All sensors share the same hidden factors. When sensor 0 is old, the GRU does not use the fresh sensors instead.

Wrong if: outages on the other sensors matter as much as outages on sensor 0.

3. Experiments and why we chose them

Two tools make the experiments fair.

  • A Kalman filter as a measuring stick. The data comes from a known linear model. We recovered its exact parameters from the data generator. A Kalman filter with these parameters gives the best possible forecast from the same 24 steps. If the Kalman filter also loses accuracy under blocks, information is really lost. If only the GRU loses, the model is the problem. The Kalman filter is a tool for measurement, not a competing method.
  • Paired windows. Every model and every mask is scored on the same windows and the same targets. A mask only removes inputs. So a difference between masks cannot come from easier or harder windows.

4. Results

Main result: the information is still there

The orange part is the gap of the Kalman filter. This is the information that the block mask really removes. The blue part is the extra gap of the GRU. It is 52% to 90% of the total, in 3 of 3 seeds. So the GRU loses accuracy that a better model keeps.

H1: old values at the origin start the problem Trigger, not cause

The block mask makes sensor 0 old at the origin in about 1 in 5 windows. The scatter mask does this in about 1 in 50.

On the same windows, persistence loses nothing when sensor 0 is fresh. The GRU loses most there too. But at age 5 and more, the Kalman filter loses several times less on the same windows (3 of 3 seeds). So the old value starts the problem, but the GRU makes it much worse.

The x axis is not to scale. Ages 1 to 4 have only 11 to 45 windows per seed, so those points are noisy. The old-value windows come from only 21 to 23 different outages per seed. E2 below is the cleaner test.

H2: lost history does not matter Rejected

We moved one 8-step outage through each window. An outage that ends 8 or 16 steps before the origin costs every model about 0 (3 of 3 seeds). Only an outage that reaches the origin costs error. On sensor 0, it costs the GRU 0.049 to 0.163 MSE and the Kalman filter only 0.001 to 0.010.

The x axis is not to scale. Seed 942 dominates the mean. See the per-seed tables at the end.

H3: the GRU does not learn to trust old values less Half right

H3 is right that the problem is in the model. But training on block masks with the same budget does not fix it. It removes the gap fully in only 1 seed (941) and partly in 1 seed (942).

The next chart shows the reason. We changed the last real sensor-0 value by a small amount and measured how much the forecast moved. The best forecast trusts a value less as it gets older. The GRU trusts old values the same or more. Block training lowers the curve, but the curve stays flat. Only 4 times more training with 32 units makes it bend down a little at high age. The age input changes the block RMSE by at most 0.0003, so the GRU does not use it.

H4: old values on other sensors also hurt Holds, wider than expected

We gave block outages only to sensor 0, only to the 5 other sensors, or to all. For the GRU, both parts cost error. Each part alone costs 31% to 67% of the full GRU gap. For the Kalman filter, each part costs less than for the GRU, in 3 of 3 seeds. Sensor-0 outages alone cost the Kalman filter almost nothing. So the GRU trusts the old filled value of every sensor, not only of sensor 0. This is wider than H4 expected.

5. Why the GRU does not learn to discount old values

Sections 1 to 4 show what goes wrong. The GRU trusts an old filled value as much as a fresh one. More training, more units and block training do not fix this. This section asks why. We tested two new explanations, H5 and H6. We wrote their tests and pass marks before we ran them (research/HYPOTHESES.md, Step 1b).

H5 · memory

The memory forgets how old a value is

The GRU memory (hidden state, 8 numbers) does not keep the time since the last real reading. When an input stops changing, the memory settles to a fixed state in a few steps. After that, a 3-step-old and a 10-step-old value look the same. A readout cannot discount what the memory does not hold.

Wrong if: a simple probe reads "age 3 or more" from the memory with balanced accuracy 0.75 or more, or a new readout on the frozen memory removes half or more of the extra error.

H6 · learning signal

The targets are too noisy to teach the discount

The GRU could learn the discount, but the real targets are noisy. The useful signal for old windows is small next to the noise, so gradient descent does not find it.

Wrong if: the same GRU, trained on a clean target with no noise, still keeps more than half of the extra error, or still trusts a 9-step-old value with 0.15 or more.

The Kalman teacher uses the true model and only the readings inside the window. No future value enters an input. It is a tool to test learning, not a method we propose.

H5: the memory knows that a value is old, but not how old Partly right

A probe tells "age 3 or more" from "age 0 to 2" with balanced accuracy 0.69 to 0.81 for the scatter-trained GRU and 0.71 to 0.81 for the mixed-trained GRU. Guessing gives 0.5. By our own pass mark, this part of H5 fails in 2 of 3 seeds for the mixed-trained GRU. But this task is easy: the input mask already says "missing now" for any age of 1 or more.

So we added a harder probe after the first run. Among old windows only, is the value 3 or more steps old, or only 1 to 2? The input window answers this with accuracy 0.99 to 1.00. The GRU memory answers with only 0.64 to 0.69. The memory keeps "old or not" and loses "how old".

The dynamics show why. When the input is held fixed, each step of change in the memory is 0.47 to 0.52 times the step before. The Jacobian has a largest eigenvalue of 0.59 to 0.65 (1 would mean perfect memory). So the memory settles in about 3 to 5 steps. The number of held steps k can be read back from the memory with R² of 0.15 at most.

The chart below shows the effect on the forecast. When sensor 0 stops, the Kalman filter trusts its last value less every step (0.32 → 0.00). The GRU trusts it more (0.21 → 0.29), and the curve is flat after about 3 steps. This is exactly what a memory that has settled would do.

A new readout does not help. We kept the mixed-trained GRU fixed and fit a new linear or quadratic readout from its memory. It removes at most 1% of the extra error on old windows. In 5 of 6 cases (3 seeds, 2 readouts) it makes the error larger. So the readout is not the problem. The needed information is not in the memory.

H6: a clean target does not teach the discount Rejected

Trained on the clean Kalman target, the GRU keeps 0.81 to 1.07 of the extra error of the real-target GRU. H6 needed 0.5 or less. Its trust in a 9-step-old value stays at 0.25 to 0.31. The Kalman filter gives such a value 0.01 to 0.02. Both pass marks fail in 3 of 3 seeds. So target noise is not the reason.

Two checks did not work as planned, and we report them. First, the noise doses do not give a clean trend. From no noise to full noise, the extra error on old windows changes per seed as 940: 0.058 → 0.081, 941: 0.087 → 0.091, 942: 0.415 → 0.366. It goes up in two seeds and down in one. Second, the teacher with full noise (a = 1) should match the real targets, but it gives 0.71 to 1.49 of their excess. The noise size is right, but real errors of neighbouring windows are correlated (lag-1 correlation 0.74 to 0.80), and our added noise is not. The H6 verdict does not depend on these checks: the clean teacher also keeps 0.72 to 1.13 of the error of the noisy teacher, in the same setup.

Showing old windows 5 times as often is the most telling result. It lowers trust in sensor 0 at every age, also at age 0 (0.03 to 0.09, against 0.17 to 0.20 with real targets). The extra error on fresh windows goes up in 3 of 3 seeds (real targets → old windows 5x: 940: 0.010 → 0.014, 941: 0.066 → 0.076, 942: 0.283 → 0.323). The GRU moves one fixed weight down. It does not learn a weight that depends on age.

More training starts to help a little. At 48 epochs the trust curve begins to bend down with age (trust at age 9+ is 0.13 to 0.27). But the GRU still keeps 0.58 to 0.90 of the extra error. Learning the discount is possible but very slow for this GRU.

6. Beyond the GRU and the synthetic data

Two questions remain. Is the failure a property of the recurrent memory? And does it appear on real data? We wrote six new tests and their pass marks before the runs (research/HYPOTHESES.md, Step 1c). The new models use PyTorch on CPU. The starter and the NumPy GRU are not changed.

T1-T4 · synthetic data

A small transformer

A transformer reads every step of the window directly. It has no memory that settles. If the settling memory of H5 were the cause, a transformer would trust old values less. We also train the GRU again in PyTorch with Adam, to separate the optimizer from the architecture.

T1: model failure is half or more of its gap. T2: trust at age 9+ stays 0.15 or more. T3: its representation holds "how old" (0.85 or more). T4: the Adam GRU behaves like the SGD GRU.

R1-R2 · real data

Beijing air quality

PM2.5 at 6 Beijing stations, hourly, with real gaps. We add the scatter and block masks on top. Three target stations replace the three seeds. The real test period (the last 6 months) is never loaded.

R1: windows where the target station is 3+ hours old carry half or more of the GRU gap. R2: the best linear trust falls with age, and the GRU trust does not.

The transformer has 2 layers, 2 heads and width 16, with dropout. We picked it once from 8 sizes by dev scatter RMSE. It is still 0% to 7% worse than the GRU on dev scatter. On real data there is no true model, so there is no Kalman oracle. The reference is a ridge model with one weight on each station's last value per age bin. It is a learned model, not a lower bound.

T1, T2: the transformer fails the same way Holds

For the scatter-trained transformer, 0.70 to 0.92 of the block gap is model failure (the NumPy GRU: 0.51 to 0.90). Its trust in a 9-step-old sensor-0 value is 0.12 to 0.27, against about 0.01 for the Kalman filter. T1 holds in 3 of 3 seeds and T2 in 2 of 3. The transformer trusts an old value like a fresh one, as the GRU does.

The attention does not look for the last real reading. From the last step, the attention weight on any one step is 0.036 to 0.059, close to 1/24 = 0.042. It does not change with age, and it is the same on the last real sensor-0 step and on the filled steps. A moving outage that ends 8 or 16 steps before the origin costs the transformer at most 21% of the cost at the origin, so H2 also holds for it in the main.

T3: the transformer also drops "how old" Rejected

We expected the transformer to keep the age and not use it. It does not keep it. Among old windows, a probe reads "3+ or 1-2 steps old" from its final representation with only 0.56 to 0.57, in 3 of 3 seeds below the pass mark of 0.85. The input window gives 0.99 to 1.00. When sensor 0 stops, the number of held steps can be read back with R² of 0.08 at most. So both architectures lose the age, but for the transformer it is not because of a settling memory. A model trained on mostly fresh windows has no reason to keep the age.

T4: Adam does not fix the GRU Holds

The PyTorch GRU with Adam trusts a 9-step-old value with 0.11 to 0.26 (T4 holds in 2 of 3 seeds). Its model-failure share is 0.40 to 0.90. The optimizer is not the cause. Mixed training lowers the transformer's trust at age 9+ to 0.08 to 0.19, a clean teacher gives 0.18 to 0.22, and 48 epochs give 0.07 to 0.22, but the 48-epoch transformer overfits (see the E8 table).

R1, R2: the same trust error on real data, at a smaller cost Holds

The masks behave as on the synthetic data. The block mask makes the target station 3+ hours old at the origin in 0.205 to 0.207 of windows, the scatter mask in 0.020 to 0.025. Each station has 8446 to 8630 dev windows, and the old windows come from 214 to 216 distinct outages. For the scatter-trained GRU, windows with a 3+ hour old value carry 0.48 to 0.74 of the gap (R1 holds in 2 of 3 stations).

The linear reference trusts the last value less as it gets older (Dongsi: 0.31 → 0.02, Guanyuan: 0.26 → 0.11, Tiantan: 0.16 → 0.00, age 0 → 9+). The GRU trusts it more (Dongsi: 0.16 → 0.24, Guanyuan: 0.13 → 0.20, Tiantan: 0.11 → 0.17). This holds in 3 of 3 stations, and the transformer and mixed training do not change it. A moving outage that ends 8 or 16 hours before the origin costs at most 0.0021 MSE.

But the cost is small on this data. On old windows, the GRU error is only 1% to 11% above the reference. PM2.5 changes slowly, and over 6 hours most of the error is noise that no model can predict. Here the transformer is 1% to 2% better than the GRU on dev scatter. So the wrong trust curve is general, but it matters most when the signal moves fast compared with the outage length.

7. Conclusion

Mechanism: stale-fill trust. Forward fill makes an outage look like a normal, constant reading. The GRU uses this filled value with the same weight as a fresh value. The best forecast gives it less weight as it gets older.

Scatter training almost never shows values older than 2 steps, so the GRU never needed this rule. The age information is in the input, but this small GRU does not turn it into a discount at this training budget. Block training at the same budget does not change that.

How general (Step 1c). A small transformer fails the same way: 0.70 to 0.92 of its gap is model failure, and it trusts a 9-step-old value with 0.12 to 0.27. Its attention is close to uniform and does not look for the last real reading. It also does not keep "how old". On real Beijing PM2.5 data, the GRU trust curve rises with age while the best linear curve falls, in 3 of 3 stations, but the cost there is small (1% to 11% on old windows). The cause is the training signal plus forward fill, not only the recurrent memory.

Why (Step 1b). The GRU memory settles within a few steps when an input stops changing. It keeps "this value is old" but forgets "how old". No readout can recover the discount from it. A clean target does not teach it either. With more old windows, the GRU only lowers one fixed weight for all ages. A discount that depends on age needs a multiplication of value and age, and this GRU learns that very slowly.

Limits

  • The data is synthetic: 6 sensors from 5 shared linear factors. Real sensors with nonlinear behavior were not tested.
  • Only the 8-unit starter GRU was tested, and one larger version (32 units, 4 times more training).
  • Three data seeds. The old-value results rest on about 21 to 23 outages per seed.
  • The Kalman filter knows the true model. It shows that the information is in the window. It does not show that a learned model can reach its error.
  • The probes are simple (linear and nearest neighbour). A more complex probe could find more age information in the memory. The "how old" probe was added after the first run.
  • The real data is one city and one pollutant. On real data there is no oracle, and the ridge reference is not a lower bound. The transformer is small and was sized once on dev scatter.

8. Next steps

  1. Step 2: prove the mechanism directly Keep the age of the old value the same and change only the value. Replace it with the Kalman estimate. If the extra GRU error goes away, stale-fill trust is confirmed. If it stays, the memory of the GRU is the problem.
  2. Step 3: test the missing multiplication directly Step 1b shows that the GRU cannot easily form value × f(age). Give it this product as a fixed input: (fill − mean) · exp(−γj · agej). This is the input decay of GRU-D (Che et al. 2018), so the module itself is known. The new part is the test: at the same budget, does the trust curve now follow the Kalman curve, and does the old-window error drop where a clean teacher, more old windows and a new readout did not?
  3. Step 3 alternative: a reliability score Predict the extra error of each window from how much the forecast depends on each value and how old that value is. Check on dev data if it finds bad windows better than the sensor-0 age alone.
  4. A limit that already holds On this data, the scatter-trained GRU is not reliable when any sensor is 3 or more steps old at the origin. Persistence is reliable only when sensor 0 is fresh.
  5. Freeze, then run the final test once Freeze the claim, the method and all settings. Then run --final one time. Also score scatter and block masks on the test period, so the effect of the new time period and the effect of the mask stay separate.
